## 2. 已确认的产品决策（2026-09-08 拍板）

| # | 议题 | 结论 |
|---|------|------|
| 1 | 「暂停生成」按钮 | **先做上**（正在生成页 1130-8101 双钮：后台生成 + 暂停生成）。**后端不做暂停接口**（PRD 契约红线），暂停仅为本地展示态（环停转、按钮变"继续生成"），服务端任务照常。样卡等待页(849-6541)**无底部按钮** |
| 2 | 删除项目范围 | 删除项目时**其内所有卡组一并删除**（`retain_decks=false`）。弹窗文案「**是否删除项目及所属卡组？**」 |
| 3 | 「重新生成」(849-6467) | **仅限 待确认/失败 任务**。待确认时走扩展后的 `POST /tasks/{id}/retry`：单事务硬删本次 STAGED 卡 + 原任务 ABANDONED(SUPERSEDED) + 同章节同配置新建 **DRAFT** 任务 → 重走样卡→预览→生成。确认后（COMPLETED）**不可重新生成**（保护学习记录） |
| 4 | 「完成导入」 | **不拦截**。解析中可退出（后台继续）；失败资料也允许直接完成导入，保留在项目中，可稍后重试/替换/删除 |
| 5 | 样卡 | 只能**预览问题和答案**，不能编辑、不能删除，且**不存在于最终生成的卡组中**（服务端任务样卡语义不变） |
| 6 | 章节→**部分** | 原「章节」概念 UI 文案全部改名「**部分**」（接口不变）。部分只能**选中/取消选中**，无法编辑名称、无法删除 |
| 7 | 588-1922 底部按钮 | 设计稿两按钮（导入资料 + 完成设置）**常驻**；实施后真机复核 |
| 8 | **发布延迟到确认（真门）** | 任务生成完毕**不再自动发布**：卡保持 STAGED，任务进入新状态 `AWAITING_CONFIRMATION`；用户在复审页点「完成设置」触发 `POST /tasks/{id}/confirm` 单事务发布。未确认期间卡组不进今日计划/复习队列/统计/卡组计数。**跨端一致（服务端即真相），前端不再需要本地确认标记表** |
| 9 | **确认前复审页只读** | 复审页在确认前仅可翻面查看问答；逐卡左滑编辑/删除仅在**确认后**经卡组卡片列表提供（STAGED 卡不开放 PATCH/DELETE）。这是唯一偏离 Figma 849-6467 hint 文案之处，已知情接受 |
| 10 | 右滑与状态同步 | 右滑编辑/删除文件文本卡片仅在**导入资料页**与**编辑项目页**；材料卡解析中/失败状态**同步到所有展示该卡片的界面**（导入资料、编辑项目、添加卡片组） |

补充统一口径：部分拆分规则（服务端解析时归类为若干「部分」，无法拆分则统一为一个）；正在解析是卡片非弹窗；「全选」再点一次即「反全选」（文案随之切换）。

## 4. 前端逐屏规范要点

### 4.1 添加项目 / 编辑项目（ProjectCreateScreen）
- 底部按钮常驻：`导入资料`(cardPanel 底、folder_open) + `完成设置`(primary、list_alt_check)。
- **创建模式**「导入资料」→ 直达导入资料页（`MaterialImport(themeKey, projectCreation=true)`）；原中间的「资料选择器(ProjectMaterialPicker)」页移除。**编辑模式** → `MaterialImport(projectId, themeKey)`。
- ⚠️ 现状 bug：编辑模式资料区当前读「创建向导草稿」，导致**编辑页资料区永远为空**。须改为读 Room 项目资料投影（含三态）。
- 编辑页顶栏：返回(#C8C8FF) + 右侧**删除圆钮 #BD3F3F** → 删除确认弹窗；表单内原「删除项目」入口移除。
- 资料卡：三态 + 右滑编辑/删除；失败卡点击重试（PDF=重新选文件 replace 重传）。

### 4.2 导入资料页（MaterialImportScreen）
- 文件/文本添加后**自动分析**；分析过程中可点「完成导入」退出，**后台继续**。
- 失败卡：内容 #E87F77，卡下方原因行「解析失败，原因如下：{原因}\n点击重试」，整卡点击重试。
- 「完成导入」**不被失败资料拦截**（现状有拦截，需移除）。
- 保留：搜索、添加文件/添加文本、文件/文本分组、右滑编辑/删除。

### 4.3 项目-卡组（ProjectDetailScreen）
- 空态两版：无卡组（有资料）→「暂未添加任何卡组喵。」；EMPTY 项目→「未添加学习资料时无法制作卡组喵。请先点击右上角编辑来添加学习资料喵。」。两态都显示「添加卡片组」按钮。
- 卡组卡四态（`GET /tasks?deck_id=` 取该卡组最新任务关联渲染）：
  - **卡组一·生成中**（任务 GENERATING）：卡 #E4E4FF、tile #C8C8FF(progress_activity)、「正在生成」，不可点；右滑删除。
  - **卡组二·失败**（任务 FAILED）：卡 #E87F77、tile #BD3F3F(error)、「生成失败：{原因}（最多一行）」+「点击重试」钮(#BD3F3F, replay)→`retry`；右滑删除。
  - **卡组三·待确认**（任务 `AWAITING_CONFIRMATION`，服务端状态）：常规卡 + 「点击查看」钮(#716FDD, feature_search) → 卡片列表复审页；右滑删除。无计数徽章（deck 计数为 0，STAGED 不可见）。
  - **卡组四·正常（已确认）**：现有白卡 + 学习进度面板；右滑**编辑+删除**（本页唯一带编辑的右滑）。

### 4.4 添加卡片组 / 生成设置（DeckGenerationScreen）
- 材料卡：选中=绿色系（#D6EEC9/#65AA56 系）；解析中卡显示等待态且**不可选中**；失败卡显示原因且**不可选中**；**无右滑**，hint 改「点击可选中文件。」
- 「下一步」门槛：≥1 份已就绪资料被选中（现有仅挡上传中）。

### 4.5 智能制卡·部分选择（SmartCardChapterScreen）
- 「章节」文案全部改「**部分**」：栏目标题「部分」、提示「选择要制作闪卡的部分。」
- 解析中：页顶 StatusProgressCard（80dp 环、「正在解析已选文件内容」/「已识别文件」），**无底部按钮**，可返回键离开。
- 解析失败：失败卡（#E87F77、「解析失败，点击重试」+「原因：xxx」），点击→重新选 PDF replace。
- 部分卡（222-4713 规范）：20dp 内边距、56dp tile 16 圆角；选中 #D6EEC9/green tile，未选中主题 background/主题 tile；仅点击选中/取消，**无编辑无删除无右滑**。
- 底部双钮：`全选⇄反全选`(#C8C8FF) + `下一步`(#716FDD)。默认全选。
- 「下一步」→ 立即导航样卡等待页（样卡请求已在后台发起）。

### 4.6 样卡等待页（新屏 SmartCardSampleWait）
- 标题「正在生成」；StatusProgressCard「正在生成预览卡片 / 稍安勿躁」；**无底部按钮**。
- 样卡就绪 → 自动跳卡片预览；失败 → 失败卡点击重试。

### 4.7 卡片预览（SmartCardPreviewScreen）
- 样卡=问题/答案双面卡（点击翻面）；**只读**，不可编辑/删除，不进最终卡组。
- hint 只保留「点击卡片可以查看答案。」
- `返回调整` → 回**添加卡片组**（生成设置）；左上角返回 → 回**部分选择**；系统返回键=左上角行为。

### 4.8 正在生成（SmartCardGeneratingScreen）
- StatusProgressCard，副标题按 `internal_stage`：PLANNING→已识别文件、GENERATING→正在整理内容、SCORING/PUBLISHING→正在检查结果、空→稍安勿躁。（可选增强：`completed/total_batch_count` 作进度条。）
- 底部双钮：`后台生成`(fill, #C8C8FF) → 项目-卡组；`暂停生成`(224dp, #716FDD, pause_circle) → **本地展示暂停**（服务端无暂停接口）。
- 失败 → 失败卡「生成失败，点击重试」+原因，点击重试（`POST tasks/{id}/retry`，失败任务复用样卡）。
- **生成完毕 → 任务进入 `AWAITING_CONFIRMATION` → 自动跳卡片列表复审页。**

### 4.9 卡片列表复审（CardListScreen·复审模式，读 /tasks/{id}/cards）
- 标题「卡片列表 N cards」（N=待确认卡数）；数据源 **`GET /tasks/{task_id}/cards`**（确认前唯一可读 STAGED 卡的出口）。
- **确认前只读**：可翻面查看答案；hint「点击卡片可以查看答案。」（不带左滑文案）。
- 底部双钮：`重新生成`(cycle, #C8C8FF) → `POST /tasks/{id}/retry`（201 新 DRAFT 任务）→ 样卡等待页；`完成设置`(celebration, #716FDD) → `POST /tasks/{id}/confirm` → 刷新 → 项目-卡组。
- 确认后用户经卡组进入的卡片列表（GENERATED 模式现状页）保持左滑编辑/删除——编辑能力在确认后完整可用。

### 4.10 项目 tab 项目卡右滑（ProjectScreen）
- 右滑出 编辑 + 删除（沿用既有右滑规范）；编辑→编辑项目页；删除→删除确认弹窗→`retain_decks=false`（服务端删除事务自动取消活跃任务，V25-D-17）。

### 4.11 删除确认弹窗（新组件 CuteConfirmDialog）

### 4.12 状态卡组件（StatusProgressCard，784-4624 族）

| 状态集合：`ACTIVE_TASK_STATUSES={DRAFT,SAMPLE_GENERATING,AWAITING_SAMPLE_CONFIRMATION,GENERATING}`；`TERMINAL_TASK_STATUSES={COMPLETED,FAILED,ABANDONED}` | `domain/task.py:31-44` |

**结论**：可见性隔离、原子发布点、可见卡守卫全部现成。本方案 = 把"自动执行的最后一步发布"改为"由用户确认触发"。

### 5.2 状态机变更

```
旧： GENERATING ──(PUBLISHING 阶段完成, ≥1 STAGED)──► COMPLETED（同事务发布）
新： GENERATING ──(PUBLISHING 阶段完成, ≥1 STAGED)──► AWAITING_CONFIRMATION（park，卡保持 STAGED）
     AWAITING_CONFIRMATION ──用户 POST /tasks/{id}/confirm──► COMPLETED（同事务发布）
     AWAITING_CONFIRMATION ──用户 POST /tasks/{id}/retry──► ABANDONED(completion_reason='SUPERSEDED')
                                   └─同事务新建 DRAFT 任务（重走样卡）
     AWAITING_CONFIRMATION ──项目/牌组删除──► ABANDONED(RESOURCE_DELETE，随现有取消例程)
```

- 零卡判定（`TASK_ZERO_CARDS`）**保持在 park 时点**——confirm 不做业务校验，只做发布（"≥1 STAGED"由 park 不变量保证）。
- `_finish_planning_empty`（`completion_reason='NO_GENERATION_UNITS'`）不经过 PUBLISHING，**直接 COMPLETED、不经过待确认**（无卡片可确认，维持现状）。

**新状态 `AWAITING_CONFIRMATION` 的归属**：

| 集合/规则 | 归属 | 说明 |
|---|---|---|
| `TERMINAL_TASK_STATUSES` | 否 | 非终态，用户动作才终结 |
| `ACTIVE_TASK_STATUSES` | **是（新增）** | 删除保护：阻塞章节删除；项目/牌组删除时被自动取消 |
| `PRE_GENERATION_TASK_STATUSES`（可 abandon） | 否 | 用户放弃路径 = retry 或删卡组；不扩展 abandon，避免三义 |
| 任务级 `DELETE /tasks/{id}` | 拒绝（409 TASK_STATE_CONFLICT） | 保持"仅终态可删" |
| retry 可接受状态 | **是（新增，与 FAILED 并列）** | 见 5.4 |
| 执行器扫描/租约 | 否 | 静止态：无 worker 工作 |
| 前端观察引擎 | 静止集 | 转出该状态的唯一途径是用户自己的请求，无需轮询 |

### 5.3 执行器改造：park 代替自动发布

改动点 `services/tasks/executor.py`：

1. `publish_generated_cards` 重构为 `park_generated_cards`，同一短事务内：CAS 守卫不变（`WHERE status='GENERATING' AND stage='PUBLISHING'` + 租约谓词）；清点 STAGED，**0 张 → FAILED/TASK_ZERO_CARDS 分支保持不变**；≥1 张 → `status='AWAITING_CONFIRMATION', stage=NULL, generated_card_count=<staged>`，lease 清理 + `finish_operation` + `bump_project_version`。**不更新 cards，不写 ended_at**。
2. `_execute_scoring_task` 的 PUBLISHING 孤儿接管路径：原"接管后自动发布"改为"接管后 park"（恢复语义不变，落点变更）。
3. `ended_at` 仅在 confirm（或 FAILED/ABANDONED）时写入。
4. **park 不变量**（测试断言）：`AWAITING_CONFIRMATION` 任务必有 ≥1 张 STAGED 卡；confirm 前这些卡对一切用户读不可见。

### 5.4 接口契约

**(a) 新增 `POST /tasks/{task_id}/confirm` —— 确认生成结果并发布**

| 项 | 值 |
|---|---|
| 认证 | Bearer（跨用户 404 `TASK_NOT_FOUND`） |
| 幂等 | `Idempotency-Key`（UUID）必填，`execute_idempotent`；同键同体重放首次 200 |
| 请求体 | 无 |
| 成功响应 | `200`，`Task` 视图（`status='COMPLETED'`，含 `generated_card_count`、`ended_at`） |
| 前置 | `status='AWAITING_CONFIRMATION'`，否则 `409 TASK_STATE_CONFLICT`（「仅待确认任务可确认发布」） |
| 其他错误 | `404 TASK_NOT_FOUND`；**不新增错误码**（registry 不动） |

事务步骤（`BEGIN IMMEDIATE`，单事务）：
1. CAS `UPDATE tasks SET status='COMPLETED', ended_at=now WHERE task_id AND user_id AND status='AWAITING_CONFIRMATION'`；rowcount=0 → 409。
2. `UPDATE cards SET publication_state='PUBLISHED' WHERE source_task_id AND publication_state='STAGED'`。
3. `generated_card_count=<实际发布数>`；`bump_project_version`；`finish_operation(reason="USER_CONFIRMED")`。

并发规则：双端同时确认——同幂等键重放 200，不同键后者 CAS 失败 409；confirm 与 retry 竞态——都 CAS 于 `AWAITING_CONFIRMATION`，串行化后一方 409，无中间态。发布瞬间即进入调度（`ReviewState` 行生成期已存在，翻转 publication_state 后立即对队列/计划/统计可见，**无需调度回填**）。

**(b) 扩展 `POST /tasks/{task_id}/retry`**

| 来源状态 | 行为 |
|---|---|
| `FAILED` | **不变**：复用已确认样卡→新任务 AWAITING_SAMPLE_CONFIRMATION，否则 DRAFT |
| `AWAITING_CONFIRMATION` | **新增**：单事务——CAS 原任务→`ABANDONED`+`completion_reason='SUPERSEDED'`+`ended_at`；**硬删除**其全部 STAGED 卡（此时不可能有学习记录）；新建 `DRAFT` 任务（复制 `selected_chapters`/`generation_config`，`retry_of_task_id` 指向原任务，**不携带样卡**——重走样卡流程）；`bump_project_version`。幂等 operation `behavior_version` 升为 `"generation-retry-v2"`。响应 `201` 新任务视图 |
| 其他 | `409 TASK_STATE_CONFLICT`（不变） |

> 不用「DELETE 任务+新建」两步：两请求间存在失败窗口（旧卡已删、新任务未建）。

**(c) 新增 `GET /tasks/{task_id}/cards` —— 复审页数据源**

- Bearer；跨用户 404；读接口无需幂等键。
- 前置 `status='AWAITING_CONFIRMATION'`，否则 `409 TASK_STATE_CONFLICT`（「仅待确认任务可查看生成卡」；确认后走 `GET /decks/{deck_id}/cards`）。
- 响应 `200 {"items": [Card]}`（schema 复用 `app/schemas/cards.py`），按 `position, card_id` 排序。按 `source_task_id` 查询并**显式绕过 visible predicate**（唯一 sanctioned 的 STAGED 读出口，代码注释标明）。

**(d) `GET /tasks` 新增可选过滤 `deck_id`**：`GET /tasks?project_id=&status=&deck_id=`——前端渲染卡组四态用。无 `deck_id` 行为不变（向后兼容）。

**(e) 接口不做什么（防歧义清单）**：不新增 pause/resume/cancel；不扩展 abandon 至待确认态；不开放任务级 DELETE 于待确认态；不改 decks/study/stats/review 任何接口（STAGED 不可见性由既有谓词覆盖）；不新增 Deck schema 字段（卡组↔任务关联由前端 `GET /tasks?deck_id=` 推导，Deck 响应保持"仅派生进度"契约 §3.8）。
