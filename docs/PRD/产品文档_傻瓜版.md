# 闪卡 App 产品设计说明（白话版）

| 项目 | 说明 |
| --- | --- |
| 面向读者 | 产品设计师、视觉设计师、交互设计师，以及参与讨论的非技术同学 |
| 对应版本 | MVP v2.1 |
| 本文目的 | 说明用户能做什么、每个页面该显示什么、发生异常时怎么提示；不要求理解后端技术细节。 |

> 一句话理解产品：用户把一份有目录的电子 PDF 教材交给 App，选中想学的章节，App 帮他生成可复习的闪卡；用户随后用“忘记 / 模糊 / 记得”来复习，看到自己的学习进度。

---

## 1. 先理解几个词

| 产品里的说法 | 大白话解释 | 设计上应怎么表达 |
| --- | --- | --- |
| PDF 制卡 | 用一份教材 PDF 自动做闪卡 | 说“从 PDF 生成闪卡”，不要对用户说“解析任务”。 |
| 牌组 | 一组放在一起学习的卡片，例如“高数第一章” | 是用户能看到、进入和删除的内容容器。 |
| 样卡 | 正式生成前先给用户看的 3 张示例卡 | 它们只用于确认风格，不会被保存到牌组。 |
| 正式卡片 | 用户确认样卡后，真正保存进牌组、以后可以复习的卡 | 牌组详情和复习中看到的是正式卡片。 |
| 开始复习 | 只练习“现在该复习”的卡片 | 当没有到期卡片时，展示完成状态。 |
| 自由刷题 | 把牌组里的所有卡随意翻看 | 不记录成绩，也不会改变之后的复习安排。 |
| 已掌握 | 一张卡至少被成功推进过 3 次 | 用于牌组进度和数据页的统计。 |

---

## 2. 产品想帮用户完成什么

用户完成一次完整体验的路径如下：

```text
上传 PDF
→ 确认章节和页码
→ 选择要学习的章节
→ 选择保存到哪个牌组
→ 设置生成偏好
→ 看 3 张样卡
→ 确认后生成正式卡片
→ 在牌组中复习
→ 在数据页看到真实学习结果
```

设计的第一优先级是让用户始终知道三件事：

1. 我现在进行到哪一步；
2. 接下来要做什么；
3. 出错后我能否重试或继续。

不要把“知识点、批次、评分、缓存、任务游标”等内部处理过程直接塞给用户。它们只需要转化为容易理解的进度、结果和异常提示。

## 3. 用户能做与不能做的事

### 3.1 本期可以做

- 上传可复制文字、有目录的 PDF 教材；
- 修改系统识别到的章节名和起止页；
- 选择一个或多个章节；
- 新建牌组，或将卡片加入已有牌组；
- 选择卡片覆盖程度、难度比例，并补充本次生成要求；
- 查看、重新生成和确认样卡；
- 在生成中断后继续生成；
- 新建问答卡，或从粘贴文本、`.txt`、`.md` 导入问答卡；
- 在导入前逐张修改导入的卡片；
- 复习到期卡，或自由浏览全部卡片；
- 删除自己创建的整个牌组；
- 查看学习进度和学习数据；
- 设置深浅主题，验证 DeepSeek API Key 的可用性。

### 3.2 本期不能做：设计中不要暗示支持

- 不支持扫描版、照片版、无文字层的 PDF；不提供 OCR 扫描识别入口；
- 不支持有密码的 PDF；
- 不保证正确识别复杂公式和复杂表格；
- 识别出的章节不能拆成更小部分、合并，也不能拖动排序；
- 识别不到目录时，不能让 AI“猜目录”或直接用整本书制卡；
- 不支持选择题、填空题；只支持问答卡和判断题；
- 样卡不能直接修改；
- 不提供正式卡片的正文编辑、排序和单张删除；
- 不会自动把质量不佳的卡片修好、删掉或额外补卡；
- 不支持卡片跳回教材原文的位置；
- 当前没有登录、注册、找回账号、手动同步或跨设备冲突处理。

设计提示：对于限制，不必在首页堆满说明。请在上传、章节确认、卡片管理等用户真正遇到限制的位置，给出简短明确的解释和可行动的下一步。

## 4. 核心流程一：从 PDF 生成闪卡

### 4.1 上传 PDF

**用户目标**：把教材交给 App，开始制作卡片。

**页面应包含**：

- 上传入口；
- 已上传或最近使用资料列表；
- 文件名、最近使用时间等容易识别的信息；
- 删除资料入口；
- 上传中、上传成功、上传失败状态。

**用户操作与反馈**：

| 情况 | 页面应如何回应 |
| --- | --- |
| 正在上传 / 读取 | 显示明确的进行中状态，例如“正在读取教材目录…”。避免让用户误以为应用卡死。 |
| 上传并识别成功 | 自动进入“确认章节”步骤。 |
| PDF 没有可用目录 | 停止后续制卡流程，说明“未识别到可用目录，暂时无法从这份资料生成闪卡”。可保留“返回资料库”按钮。 |
| 文件解析或生成失败 | 原 PDF 仍留在资料库，用户可稍后重试或用它重新建任务。 |
| 用户删除资料 | 需要二次确认，明确说明“删除后不能再用这份 PDF 创建新任务”。 |

**文案建议**：

- 上传前：`上传有文字和目录的 PDF 教材`
- 不支持时：`这份 PDF 需要有可识别的文字和目录。扫描件、图片型文件或加密文件暂不支持。`
- 识别中：`正在识别目录和页码，请稍候`

同一份 PDF 可以多次用来制作不同牌组或不同难度的卡片，因此不应把“已使用”设计成不可再次选择。

### 4.2 确认章节

**用户目标**：确认系统理解的是哪几章，并选出自己想学习的内容。

**页面结构建议**：

- 顶部说明：`确认教材章节`；
- 章节列表，每项至少展示：章节名称、开始页、结束页、选择状态；
- 可编辑章节名称、开始页、结束页；
- 多选控件；
- 底部主按钮：`下一步`。

**关键规则**：

- 用户可改名字和页码，但不能拆分章节、合并章节、改变章节顺序；
- 可以选择一个或多个章节；
- 未选任何章节时不能继续，应说明“请至少选择一个章节”；
- 章节识别失败时根本不进入这个页面。

**要避免的误导**：不要放置“智能补全目录”“拖动排序”“拆分本章”等入口，也不要承诺 App 会理解或处理全部复杂图表和公式。

### 4.3 选择牌组

**用户目标**：决定生成的卡片存到哪里。

用户必须二选一：

1. 新建牌组：填写牌组名；
2. 加入已有牌组：从已有牌组中选择一个。

没有选择牌组时不可进入下一步。加入已有牌组的含义是“在原有内容后继续添加”，绝不能让用户担心已有卡片会被覆盖。

### 4.4 设置生成偏好

**用户目标**：告诉 App 想要生成得少一点还是覆盖得更全面，以及难度偏好。

#### 覆盖程度

提供三档单选：

| 选项 | 面向用户的解释 |
| --- | --- |
| 精简 | 抓住最重要的内容，适合快速复习。 |
| 均衡 | 覆盖重点知识，兼顾数量和完整度。 |
| 充分覆盖 | 尽量覆盖更多知识点，适合系统学习。 |

这不是“固定生成多少张”。页面不可写死卡片数量，也不要暗示会为了凑数而生成重复内容。

#### 难度比例

让用户通过三档比例理解卡片构成：

| 难度 | 大白话说明 | 默认比例 |
| --- | --- | --- |
| 基础记忆 | 记定义、事实和直接结论 | 40% |
| 理解分析 | 理解原因、关系和差别 | 40% |
| 综合应用 | 把多个知识点放进场景里思考 | 20% |

- 三项默认是 40% / 40% / 20%；
- 用户本次调整后，会成为下一次新建任务的默认难度比例；
- 用户填写的“自定义生成要求”只对本次有效，下一次不自动带入；
- 综合应用卡可能会同时考多个知识点，这是正常的。

#### 自定义生成要求

提供可选的多行输入框，帮助文本可为：`例如：更偏重考试易错点；尽量用生活化例子。`

不要把该输入框设计成永久偏好或默认配置标签，因为它只属于当前任务。

### 4.5 样卡预览与确认

**用户目标**：在批量生成前确认“卡长什么样、难度是否合适”。

系统每次固定展示 3 张样卡：

- 1 张基础记忆；
- 1 张理解分析；
- 1 张综合应用；
- 三张里固定有 2 张问答卡、1 张判断题。

样卡页需要让用户看出难度标签和卡片类型，且能翻面查看答案或解析。用户有三种选择：

| 操作 | 结果 |
| --- | --- |
| 接受样卡 / 开始生成 | 进入正式生成。 |
| 修改偏好 | 回到配置页，重新生成 3 张新样卡。 |
| 取消 | 本次制卡结束，不产生正式卡片。 |

**必须讲清楚的边界**：

- 样卡不能编辑；
- 样卡不会保存到牌组，不会出现在复习里，也不算入最终生成数量；
- 教材内容不足时，样卡允许采用合理示例来展示形式。因此可以加弱提示：`样卡用于确认题型和难度，正式卡片会基于你选中的章节生成。`

### 4.6 正式生成与生成进度

用户确认样卡后，App 将按教材知识点逐步制作并保存正式卡片。

**设计目标**：用户不需要理解系统如何分批处理，只需要看到可信的任务状态。

页面至少区分以下状态：

| 状态 | 用户应看到 | 推荐行动 |
| --- | --- | --- |
| 生成中 | “正在生成闪卡”，已生成张数、目标牌组 | 等待；如产品已有取消入口可取消。 |
| 暂停 / 网络异常 | “生成已暂停，已完成的卡片已保存” | `继续生成`、`重试`。 |
| 可继续 | 清楚说明还有未完成的内容 | `继续生成`。 |
| 已完成 | “已生成并保存 X 张卡片” | `查看牌组`、`去复习`。 |
| 失败且不可恢复 | 说明失败原因，保留返回入口 | `重试`或返回资料库。 |

**重要体验规则**：

- 中断并不等于前功尽弃：已经生成并保存的卡片会保留；
- 用户点“继续”后，只补做未完成的部分，不能重复增加已有卡片；
- 网络失败或超时时，保留用户当前上下文，提供重试；
- 不要展示“批次、游标、幂等键、Schema、Rubric、缓存 Token”等技术词。

### 4.7 正式卡片的类型与质量

正式卡片只有两种：

- **问答卡**：正面是问题，翻面看答案；
- **判断题**：展示一句说法，用户判断对错，再看解释。

系统会检查卡片最基本的结构是否齐全，例如问答卡是否同时有问题和答案，判断题是否有陈述、对错和解释。只有结构完整的卡才会进入牌组；如果生成结果不完整，系统会在有限次数内尝试重新生成。

系统也会在后台记录卡片质量，帮助团队未来改进生成效果。但这份内部评分不会自动删除、修复或拦截已经结构完整的卡片。设计上无需展示分数，也不要设计“低分卡自动消失”的状态。

### 4.8 单卡重新生成

产品需求中保留了“对一张正式卡片重新生成并替换”的能力：

```text
用户请求重新生成
→ App 生成新版本
→ 新版本合格后替换旧卡
→ 失败则保留旧卡
```

设计原则是“替换要安全”：重新生成失败时，原卡必须仍可用。可采用加载状态、结果确认或错误提示，不能先把旧卡清空。

> 注意：当前前端只有示例性质的“AI 重新生成”弹窗，尚未能选择并替换真实卡片。这一功能是否在 v2.1 实现，仍需产品与研发确认；见第 9 章。

## 5. 核心流程二：牌组与手动导入

### 5.1 牌组列表

牌组是用户的学习入口。列表中的每个牌组建议展示：

- 名称；
- 总卡片数；
- 当前待复习数；
- 进度概览；
- 创建来源可以在需要时区分为“AI 生成 / 手动创建 / 文本导入”，但不必抢占主视觉。

数据必须来自真实保存的结果，不能继续使用演示卡片或固定数字冒充用户数据。

### 5.2 新建与添加卡片

用户可以：

- 新建一个空牌组；
- 往已有牌组添加手动问答卡；
- 把 PDF 生成的卡加入已有牌组；
- 把文本导入的卡追加到已有牌组。

手动新增卡片时，问题和答案都不能为空。保存成功后卡片应稳定地出现在牌组中；重复点击或网络重试不能产生两张一模一样的卡。

### 5.3 从文本导入卡片

支持两种输入方式：粘贴文本，或选择 `.txt` / `.md` 文件。

用户内容的基本含义是“一问一答”。客户端可识别常见的写法，例如：

```text
Q: 什么是光合作用？
A: 植物利用光能合成有机物的过程。

问题：什么是牛顿第一定律？
答案：物体不受外力时保持静止或匀速直线运动。
```

也可以兼容 Markdown 标题和空行分段。导入流程建议是：

```text
粘贴 / 选择文件 → 解析 → 预览卡片 → 逐张修改 → 确认保存
```

**预览页是本期唯一可以编辑卡片正文的地方**。用户可在此修改即将导入的每张卡。无法识别的段落不应被悄悄丢弃：页面要指出对应的行或段落，并说明如何修改格式。

### 5.4 删除牌组

删除的是整个牌组，连同其中的卡片、复习安排和相关学习记录一起删除。因为本期没有单卡删除能力，删除入口尤其需要谨慎：

- 使用二次确认；
- 写明影响，例如：`删除后将移除该牌组中的所有卡片和复习记录，且无法恢复。`
- 重复提交删除请求不应产生异常页面；最终显示“已删除”即可。

## 6. 核心流程三：复习与学习进度

### 6.1 两种学习模式

| 模式 | 用户看到的内容 | 是否记录结果 |
| --- | --- | --- |
| 开始复习 | 现在到期、应该复习的卡片 | 是。每次评级都会影响以后何时再出现。 |
| 自由刷题 | 牌组中的全部卡片 | 否。只供浏览和自测，不改变学习安排。 |

这两个入口和页面说明必须清楚区分，避免用户在自由刷题后以为进度已更新。

### 6.2 复习一张卡

推荐的基本交互：先展示题面，用户翻面查看答案或解释，然后选择一个评级：

- **忘记**：完全没想起来；
- **模糊**：有印象，但不够确定；
- **记得**：能正确回忆。

前端已有的按钮文案、手势和结果必须保持一致。一个评级成功提交后，系统会保存本次复习，并更新这张卡下一次出现的时间、牌组进度和统计数据。

复习间隔会按阶段逐步拉长，基础节奏是 10 分钟、1 天、3 天、7 天。用户不必看到复杂算法；若需要展示，可使用直白的结果文案，例如“下次复习：明天”。选择“忘记”会回到较早阶段，选择“模糊”或“记得”通常会继续往后推进。

### 6.3 空状态与离线情况

- 没有到期卡时：展示庆祝或完成状态，例如“今天的待复习卡已完成”；可提供“自由刷题”入口；
- 自由刷题的结束页：不要显示“已计入学习进度”；
- 网络暂时不可用时：复习操作需要可靠暂存，恢复网络后再提交；用户不应因为重试而让同一次复习被重复计数；
- 成功提交后，数据页可能稍后才同步更新。若出现延迟，展示“数据正在更新”比显示旧的假数据更好。

### 6.4 牌组进度

牌组详情至少需要清楚呈现：

- 总卡片数；
- 待复习数；
- 已掌握卡片数；
- 总复习次数；
- 掌握进度。

“已掌握”在本期的统一含义是：一张卡已成功推进至少 3 次。掌握进度 = 已掌握卡数 ÷ 总卡数；当牌组为空时，展示 0 或合适空状态，不能出现无意义的百分比。

## 7. 核心流程四：数据看板

### 7.1 数据页原则

数据页展示的是用户真实的复习数据，不是装饰性的固定数字或固定柱状图。默认查看本周；一周从周一开始，日期计算以用户所在时区为准。

没有数据时请用空状态，例如“完成一次复习后，这里会显示你的学习趋势”，而不是用 0% 来假装某种表现。

### 7.2 需要展示的指标

| 指标 | 对用户的解释 | 设计注意点 |
| --- | --- | --- |
| 周活动 | 本周每天复习了多少次，以及全周总次数 | 可使用按天柱状图；无数据要显示空态。 |
| 周变化 | 本周比上周多还是少复习 | 上周没有复习时显示“暂无对比”，不要显示无穷大或 0%。 |
| 周目标完成率 | 本周已完成多少学习目标 | 用户未设置周目标时显示“未设置目标”或不展示比例。 |
| 回忆正确率 | 本周期里，选择“记得”的比例 | 没有任何复习记录时显示“暂无数据”。 |
| 首次答对率 | 第一次见到一张卡时，选择“记得”的比例 | 解释要和总体正确率区分开。 |
| 记忆保持率 | 不是第一次复习时，仍选择“记得”的比例 | 没有复习过旧卡时显示“暂无数据”。 |
| 连续学习天数 | 到今天为止，连续每天至少复习一次的天数 | 以用户本地自然日计算。 |
| 已掌握卡片 | 已推进至少 3 次的不同卡片数量 | 是卡片数，不是复习次数。 |

当某一指标的计算基础为零时，应该显示“暂无数据”而非 `0%`。`0%` 的含义是“确实有数据，但结果为零”，二者不能混用。

## 8. 设置、安全与系统提示

### 8.1 主题

支持：跟随系统、浅色、深色。主题偏好当前只保存在本机；设计中不应标注“已同步到云端”。

### 8.2 DeepSeek API Key

用户可以在设置页“验证并保存”自己的 API Key。页面至少需要表达四种结果：

| 结果 | 建议展示 |
| --- | --- |
| 可用 | `API Key 可用，可以开始生成闪卡` |
| 无效 | `API Key 无效，请检查后重试` |
| 余额不足 | `API Key 余额不足，请充值后重试` |
| 其他失败 | `暂时无法验证，请稍后重试` |

安全体验要求：

- Key 输入框必须默认隐藏内容；
- 成功后仅显示脱敏信息或状态，绝不回显完整 Key；
- 任何错误提示、任务详情和分析页面都不得出现完整 Key；
- 当前“Key 不上传服务器”的前端提示，与服务端生成任务的实现方式存在待确认冲突，不能作为最终承诺，见第 9 章。

### 8.3 通用异常提示原则

- 提示用户能理解的原因和下一步，例如“网络连接失败，请重试”；
- 可恢复的问题要有明确的 `重试`、`继续生成` 或返回入口；
- 不展示原始接口报错、错误码、服务器术语；
- 长任务必须区分“生成中 / 已暂停可继续 / 已完成”；
- 服务端数据是最终结果，本地演示数据、缓存或临时页面不能伪装成已成功保存。

## 9. 目前需要产品确认的 4 个问题

这些问题会直接改变部分页面和交互，设计师在定稿前应和产品、研发确认。

| 编号 | 需要决定什么 | 对设计的影响 |
| --- | --- | --- |
| D-01 | 判断题是否保持“陈述 + 对错 + 解释”的独立形式，还是本期统一显示成普通问答卡？ | 决定卡片预览、复习页和导入/详情页是否需要判断题专属样式与操作。 |
| D-02 | 数据归属采用匿名设备 ID（不跨设备）还是加入账号登录？ | 决定是否需要登录/绑定入口，以及“本机数据”“跨设备同步”等文案。 |
| D-03 | 用户的 DeepSeek Key 是否在请求时安全传给后端、只短暂使用，还是改为手机直连模型？ | 决定设置页隐私说明、授权提示和生成流程的责任边界。 |
| D-04 | “单卡重新生成并替换”是否真正在 v2.1 上线？ | 若上线，需要在真实卡片详情提供入口、加载、失败保留旧卡和刷新结果；若不上线，应移除当前示例入口。 |

## 10. 设计验收清单

在交付设计稿前，可逐项检查：

- [ ] 上传页明确支持“有文字和目录的 PDF”，并对不支持文件有说明；
- [ ] 目录无法识别时有停止流程和返回路径，而不是跳过章节确认；
- [ ] 章节页可编辑名称和起止页、可多选，未选章节不能继续；
- [ ] 配置页说明“覆盖程度不是固定卡片数量”，三档难度默认比例正确；
- [ ] 样卡页固定体现 3 张、三种难度、两问答一判断，并明确样卡不保存、不能编辑；
- [ ] 生成页包含进行中、暂停可继续、完成和失败状态；中断后明确已完成内容会保留；
- [ ] 牌组可以新建、追加和导入；导入预览可逐张编辑且能指出无法识别的内容；
- [ ] 删除牌组有清楚的不可恢复提示和二次确认；
- [ ] “开始复习”与“自由刷题”入口及结果差异足够清楚；
- [ ] 复习页的“忘记 / 模糊 / 记得”按钮、手势和说明一致；
- [ ] 数据页所有数字都支持真实数据、无数据和更新中的状态，不使用演示数字；
- [ ] API Key 永不明文回显，验证结果有可理解的状态；
- [ ] 没有在非技术页面展示 Schema、Rubric、批次、游标、Token 等内部术语；
- [ ] 第 9 章的待确认项在对应设计稿中标记为待定，避免设计先行固化错误方案。

## 11. 给设计师的最终提醒

这个 MVP 追求的不是“AI 自动做出完美卡片”，而是让用户可靠地走通：**上传资料、确认范围、确认样卡、获得可复习的正式卡片、看到真实学习结果**。

因此，设计上最重要的是：

- 让用户在每一步都有掌控感；
- 把生成时间较长、可能中断的过程说清楚；
- 把样卡与正式卡片区分清楚；
- 把“浏览”和“会计入进度的复习”区分清楚；
- 诚实展示失败、无数据和待确认的能力边界。
