## 1. 产品概述

### 1.1 产品目标

用户上传具有可解析文本层和目录结构的 PDF，选择需要学习的章节并配置生成偏好后，系统使用用户提供的 DeepSeek API Key 生成闪卡，并将符合数据结构要求的卡片写入指定牌组。

MVP 的核心目标是验证以下链路能否稳定、完整地运行：

1. 解析 PDF 及其目录结构；
2. 生成样卡并获得用户确认；
3. 按知识点分批生成正式卡片；
4. 将合法卡片写入目标牌组；
5. 在任务中断后从断点继续生成，且不重复执行或入库。
6. 让牌组、卡片和复习结果有可持久化、可同步的服务端数据来源。
7. 基于真实复习数据展示学习进度和数据看板。

### 1.2 产品原则

- 优先保证核心制卡链路稳定可用。
- Schema 校验是卡片能否入库的唯一质量门槛。
- Rubric 评分仅用于质量观测，不参与入库、修复或淘汰决策。
- MVP 不构建自动修复、自动补生成或多轮质量优化闭环。

### 1.3 支持的卡片类型

MVP 支持：

- 普通问答卡；
- 判断题。

MVP 不支持：

- 填空题；
- 选择题。

## 2. 核心术语

| 术语 | 定义 |
| --- | --- |
| 生成任务（Task） | 用户基于一个 PDF、所选章节及生成配置发起的一次完整制卡任务。 |
| 样卡（Sample Card） | 正式生成前用于展示卡片形式和难度差异的 3 张预览卡片，不属于正式学习内容。 |
| 正式卡片（Card） | 用户确认样卡后生成，并在通过 Schema 校验后写入牌组的卡片。 |
| 知识点（KnowledgePoint） | 系统从所选章节中规划出的生成单元，用于控制覆盖范围和分批执行。 |
| 生成批次（Batch） | 正式生成过程中一次可独立执行、记录和恢复的处理单元。 |
| 任务游标（Cursor） | 标识任务当前处理位置的数据，用于断点续传。 |
| Schema 校验 | 对卡片字段及数据结构进行合法性校验，是卡片入库的必要条件。 |
| Rubric 评分 | 从原文依据、答案正确性、难度匹配和学习价值四个维度记录卡片质量。 |
| 牌组（Deck） | 用户学习内容的容器，可新建、导入、追加卡片或作为 PDF 制卡结果的归属。 |
| 复习状态（Review State） | 一张卡当前的下次复习时间、间隔阶段、掌握次数及最近一次评级。 |
| 复习事件（Review Event） | 用户对一张卡执行“忘记 / 模糊 / 记得”评级后产生的不可变记录。 |
| 自由刷题 | 不受待复习时间限制、浏览牌组全部卡片的学习模式；不产生复习评级。 |
| 数据看板 | 按真实复习数据聚合的周活动、掌握度、正确率、连续学习天数等指标。 |

## 3. 产品范围

### 3.1 本期范围

- 上传并保存 PDF；
- 解析 PDF 文本层及目录结构；
- 确认或修改章节名称与页码范围；
- 选择一个或多个章节；
- 新建牌组或选择已有牌组；
- 配置数量倾向、难度比例和自定义生成要求；
- 生成、展示及重新生成样卡；
- 规划知识点并分批生成正式卡片；
- 执行 Schema 校验和 Rubric 评分；
- 将 Schema 合法的卡片写入牌组；
- 记录批次质量数据和 Prompt Cache 数据；
- 支持任务断点续传、幂等控制和单卡重写。
- 新建牌组、向已有牌组追加卡片，以及从文本或 `.txt` / `.md` 文件导入问答卡；导入前可预览并逐张修改。
- 删除用户创建的牌组及其卡片。
- 间隔复习和自由刷题；记录“忘记、模糊、记得”三种复习评级。
- 展示牌组进度与数据看板：周活动、周目标、回忆正确率、首次答对率、记忆保持率、连续学习天数和已掌握卡片数。
- 保存主题偏好；校验 DeepSeek API Key 并展示可用、无效或余额不足状态。

### 3.2 本期不包含

- OCR、扫描版 PDF 和图片型教材解析；
- 密码保护 PDF；
- 复杂公式的视觉解析；
- 复杂表格的结构化解析；
- 章节拆分、合并和拖拽排序；
- 目录解析失败后的 AI 猜测或整文兜底；
- 选择题和填空题；
- 样卡编辑；
- 自动修复、自动淘汰和自动补生成；
- 语义去重、自动重平衡、自动裁剪和多轮质量优化；
- 卡片来源跳转原文；
- 可视化运营后台；
- KMS、文件级加密系统、自动化数据生命周期管理和多级备份清理策略；
- 复杂数据治理系统。
- 用户登录、注册、账号找回、跨设备冲突处理界面和手动同步入口（如要提供云端数据同步，需另行确认账户归属方案）。
- 卡片正文的编辑、排序和单独删除；当前前端仅支持导入预览阶段编辑，以及删除整个牌组。

## 4. 核心用户流程

### 4.1 主流程

1. 用户上传 PDF。
2. 系统解析 PDF，并识别章节名称及对应页码范围。
3. 用户确认章节信息，或修改章节名称、起始页和结束页。
4. 用户选择一个或多个章节。
5. 用户选择新建牌组或已有牌组作为卡片归属。
6. 用户配置数量倾向、三档难度比例和自定义生成要求。
7. 系统生成并展示 3 张样卡。
8. 用户接受样卡，进入正式生成流程。
9. 系统构建知识点清单，并按批次生成正式卡片。
10. 系统对生成结果执行 Schema 校验和 Rubric 评分。
11. 系统将通过 Schema 校验的卡片写入目标牌组，并更新任务游标。
12. 所有批次完成后，任务结束。

### 4.2 样卡阶段的用户分支

| 用户操作 | 系统行为 |
| --- | --- |
| 接受样卡 | 进入正式生成流程。 |
| 修改配置 | 保存本次修改，并重新生成 3 张样卡。 |
| 取消任务 | 结束当前任务，不进入正式生成。 |

### 4.3 异常与恢复流程

- 目录解析失败时，终止当前流程并向用户展示错误；系统不进行 AI 猜测或整文生成兜底。
- 单次生成结果不符合 Schema 时，系统可在限定次数内重试；达到重试上限后，将该次输出记为生成失败。
- 正式生成中断时，系统保留已生成卡片、已完成批次和任务游标。
- 用户继续任务时，系统仅处理未完成部分，不重复执行已完成批次，也不重复写入已入库卡片。

### 4.4 牌组、复习与数据流程

1. 用户新建牌组，或粘贴 / 选择 `.txt`、`.md` 文件导入问答卡。
2. 客户端解析内容，展示可逐张修改的导入预览；用户可保存为新牌组或追加到已有牌组。
3. 用户从牌组详情进入“开始复习”或“自由刷题”。
4. 间隔复习仅加载到期卡片；用户翻转卡片后以“忘记、模糊、记得”评级。
5. 客户端提交复习事件；系统原子更新该卡复习状态、牌组进度和统计聚合。
6. 用户打开数据页，客户端读取指定统计周期的真实聚合数据，不使用硬编码演示数据。

### 4.5 当前前端状态与联调边界

当前 Android 前端已具备上述页面、交互和本地 Room 数据实现，但 PDF 流程、AI 重写、DeepSeek Key 校验及数据页当前均含本地 Mock / 演示状态。后端联调后：

- 服务端是 PDF 解析、AI 调用、生成任务、云端牌组 / 卡片、复习记录和统计的权威数据源；
- 客户端仍可保留本地数据库作为缓存与离线展示，但不得以本地 Mock 结果冒充服务端成功结果；
- 对写操作，客户端必须携带幂等键；服务端返回资源 ID、版本或更新时间，供客户端刷新缓存；
- 网络失败时，客户端应展示可重试状态；PDF 任务可继续，复习事件需在本地可靠暂存并最终去重提交。

## 5. 功能需求

### 5.1 PDF 上传与存储（FR-01）

#### 需求说明

系统应允许用户上传具备可提取文本层和可识别目录结构的 PDF，并保存文件供后续重复创建生成任务。

#### 业务规则

- PDF 在用户主动删除前持续保留。
- 首页展示最近使用的 PDF；用户可删除最近资料记录及对应服务端文件元数据。删除后的 PDF 不得再用于创建任务。
- PDF 解析失败或生成任务失败时，不删除原始文件。
- 用户可基于同一 PDF 创建多个生成任务。
- 文件传输必须使用 HTTPS。
- 文件访问依赖基础存储权限控制。

### 5.2 目录解析与章节确认（FR-02）

#### 需求说明

系统必须从 PDF 中解析出可用的章节名称和页码范围。未获得可用目录结构时，用户不能进入后续生成流程。

#### 用户可执行操作

- 修改章节名称；
- 修改章节起始页；
- 修改章节结束页；
- 选择一个或多个章节用于生成。

#### 限制

- 不支持章节拆分；
- 不支持章节合并；
- 不支持拖拽排序；
- 解析失败时不使用 AI 猜测章节，也不进行整文兜底。

### 5.3 牌组归属（FR-03）

用户在生成前必须指定卡片的目标牌组，可选择：

- 新建牌组；
- 加入已有牌组。

通过 Schema 校验的正式卡片应写入该目标牌组。

### 5.4 生成配置（FR-04）

#### 5.4.1 数量倾向

系统提供以下三档数量倾向：

- 精简；
- 均衡；
- 充分覆盖。

数量倾向用于控制知识覆盖密度，不代表固定卡片数量。系统不得通过重复生成相同内容来满足数量倾向。

#### 5.4.2 难度比例

系统提供以下三档难度：

| 难度 | 定义 |
| --- | --- |
| 基础记忆 | 对事实、定义和概念的直接回忆。 |
| 理解分析 | 对关系、原因和差异进行理解、对比或推理。 |
| 综合应用 | 组合多个知识点，进行场景推理或实际应用。 |

业务规则：

- 默认难度比例为基础记忆 40%、理解分析 40%、综合应用 20%。
- 难度比例对当前任务生效。
- 用户设置的难度比例在后续新任务中作为默认值继承。
- 综合应用卡可同时关联多个知识点，不要求对应单一原子知识点。

#### 5.4.3 自定义生成要求

- 用户可输入当前任务的自定义生成要求。
- 自定义生成要求仅对当前任务生效。
- 创建新任务时，不继承上一个任务的自定义生成要求。

### 5.5 样卡生成与确认（FR-05）

#### 需求说明

正式生成前，系统必须生成 3 张样卡，用于帮助用户确认卡片形式及难度差异。

#### 生成规则

- 样卡数量固定为 3 张，用户不可修改。
- 难度构成为：基础记忆 1 张、理解分析 1 张、综合应用 1 张。
- 卡片类型构成为：普通问答卡 2 张、判断题 1 张。
- 样卡优先保证结构完整，并清晰体现难度差异。
- 当 PDF 内容不足以覆盖样卡要求时，可使用合理示例或假设性情境，不要求每张样卡都能严格追溯至原文。

#### 数据规则

样卡：

- 不写入牌组；
- 不计入正式生成统计；
- 不参与 Rubric 质量评估；
- 不进入后续复习流程；
- 不影响正式生成逻辑；
- 不支持用户直接编辑。

### 5.6 知识点规划（FR-06）

正式生成前，系统应根据所选章节构建 `KnowledgePoint` 列表，用于控制生成范围和分批执行。

每个知识点至少包含以下字段：

```text
knowledge_point_id
task_id
chapter_id
source_chunk_id
topic
priority
status
```

`status` 可取值：

- `PENDING`：待处理；
- `PROCESSED`：已处理；
- `SKIPPED`：已跳过。

知识点与卡片不是一一对应关系。综合应用卡可关联多个知识点。

### 5.7 正式卡片生成（FR-07）

正式生成流程为：

```text
知识点规划
→ 分批生成
→ Schema 校验
→ Rubric 评分
→ 写入牌组
→ 更新任务游标
```

业务规则：

- 系统根据内容自动选择普通问答卡或判断题。
- 用户不能配置两种卡片类型的生成比例。
- 正式生成不包含自动修复、自动淘汰、自动补生成或自动重平衡。

### 5.8 Schema 校验与入库（FR-08）

Schema 校验是卡片能否入库的唯一判断条件。Rubric 评分不影响入库。

普通问答卡必须包含：

```text
type
question
answer
```

判断题必须包含：

```text
type
statement
answer_boolean
explanation
```

业务规则：

- 通过 Schema 校验的卡片应写入目标牌组。
- 未通过 Schema 校验的输出视为生成失败。
- 系统可对 Schema 校验失败的输出进行有限次数重试。
- Rubric 分数不得阻止 Schema 合法的卡片入库。

### 5.9 Rubric 质量评估（FR-09）

#### 评估目的

Rubric 用于分析：

- Prompt 质量变化；
- 模型版本差异；
- 不同 PDF 的内容难度差异；
- 生成质量与稳定性。

Rubric 不参与：

- 入库判断；
- 自动修复；
- 卡片淘汰；
- 自动补生成。

#### 评分维度

每个维度按 0～3 分评分，总分范围为 0～12 分。

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
| --- | --- | --- | --- | --- |
| 原文依据 | 无原文依据或与原文冲突 | 原文依据不足 | 基本可由原文支持 | 完整且可追溯 |
| 答案正确性 | 答案错误 | 存在明显问题 | 基本正确 | 完全正确 |
| 难度匹配 | 与目标难度完全不匹配 | 部分匹配 | 基本匹配 | 高度匹配 |
| 学习价值 | 无学习价值 | 学习价值较低 | 具有学习价值 | 具有核心学习价值 |

不设置“表达清晰”和“原子化”评分维度，也不定义 `PASS` / `FAIL` 状态。

#### 评分结果字段

```text
evidence_score
correctness_score
difficulty_score
learning_value_score
rubric_total_score
```

### 5.10 整批质量统计（FR-10）

系统应记录以下批次质量数据：

- 覆盖率；
- 重复率；
- 难度分布；
- 章节分布；
- 卡片类型分布；
- 难度偏差。

上述数据仅用于观测，不触发自动补生成、自动去重、自动重平衡、自动裁剪或多轮优化。

### 5.11 Prompt Cache（FR-11）

Prompt Cache 的目标是提高缓存命中率，不要求完全命中。

为提高命中率，以下稳定内容应保持结构稳定：

- System Prompt；
- Schema；
- Rubric；
- Prompt Version。

PDF 内容、章节内容及用户配置等动态内容必须放在 Prompt 后段。

系统应记录：

```text
prompt_cache_hit_tokens
prompt_cache_miss_tokens
output_tokens
```

### 5.12 任务恢复与幂等控制（FR-12）

#### 任务恢复

系统通过分批生成、任务游标和幂等 ID 支持断点续传。每个批次至少记录：

```text
batch_id
cursor
generated_item_ids
```

#### 幂等要求

以下操作必须支持幂等控制：

- 启动生成；
- 继续任务；
- 批次同步；
- 单卡重写。

每张正式卡片使用 `generation_item_id` 作为唯一标识。

业务规则：

- 已完成批次不得重复执行。
- 已入库卡片不得重复写入。
- 继续任务时，仅生成尚未完成的部分。

### 5.13 单卡重写（FR-13）

用户可对一张正式卡片发起重写。

处理流程：

```text
请求重写
→ 生成新版本
→ Schema 校验
→ Rubric 记录
→ 替换原卡
```

业务规则：

- 新版本通过 Schema 校验后替换原卡。
- Rubric 分数不影响替换结果。
- 重写失败时保留原卡，不改变原有内容。
- 系统可使用 PDF 来源信息进行 Rubric 评分，但不向用户展示该来源信息。

### 5.14 牌组与卡片管理（FR-14）

#### 需求说明

系统应为客户端提供牌组和卡片的持久化接口，使 PDF 制卡结果、手动新增卡片和文本导入卡片可进入同一牌组，并在牌组列表和详情页展示真实数据。

#### 用户操作与服务端行为

| 用户操作 | 服务端要求 |
| --- | --- |
| 新建牌组 | 创建归属于当前数据主体的牌组，返回 `deck_id`、名称、来源、创建时间和版本信息。 |
| 加入已有牌组 | 校验牌组归属后，以追加语义批量写入卡片；不得覆盖已有卡片。 |
| 手动新增卡片 | 校验 `front`、`back` 非空后创建问答卡，并分配稳定的排序位置。 |
| 导入文本卡片 | 客户端完成文本解析和预览编辑；服务端以最终确认的卡片列表进行原子批量写入，并返回逐张写入结果。 |
| 查看牌组 | 返回牌组列表、卡片数、到期数，以及牌组详情所需的真实进度汇总。 |
| 删除牌组 | 校验归属后删除牌组及其卡片、复习状态和关联统计数据；同一删除请求重复提交必须安全返回。 |

#### 业务规则

- 导入文本格式为 `问题 / 答案` 对；客户端可兼容 `Q/A`、`问题/答案`、Markdown 标题及空行分段格式。无法识别的内容不入库，并向用户返回可展示的行或段落级错误。
- 卡片批量写入必须支持 `idempotency_key`。相同主体、相同操作和相同幂等键重复请求时，返回首次成功结果，不得产生重复卡片。
- PDF 生成写入与手动 / 导入写入使用同一牌组、卡片和排序模型，但需保留 `source` 区分来源（至少包括 `generated`、`manual`、`imported`）。
- 当前前端不提供卡片正文编辑、排序或单卡删除；后端无需将其作为本期对外能力。

### 5.15 间隔复习与学习进度（FR-15）

#### 需求说明

系统应支撑“开始复习”和“自由刷题”两种学习模式。其中间隔复习的评级结果需要可靠落库，以生成后续待复习队列、牌组进度和数据看板。

#### 复习规则

- “开始复习”只返回 `next_review_at <= 当前服务端时间` 的到期卡片；排序按到期时间、牌组内位置稳定排序。
- “自由刷题”返回牌组全部卡片，仅用于浏览，不创建复习事件、不改变复习状态。
- 客户端可提交 `AGAIN`（忘记）、`HARD`（模糊）、`GOOD`（记得）三种评级。前端当前展示的文案与手势映射须保持一致。
- 每次评级必须原子创建一条 `review_event`，并更新对应 `review_state`：`next_review_at`、`interval_step`、`mastered_count`、`last_rating` 和 `last_reviewed_at`。
- 本期排程算法沿用前端已有的四档间隔：10 分钟、1 天、3 天、7 天。`AGAIN` 重置阶段和掌握次数；`HARD` / `GOOD` 推进阶段，具体 `HARD` 延迟按服务端算法统一计算。
- 同一复习事件必须携带 `client_event_id` 并保证幂等。离线补传或重试不得重复增加掌握次数、复习次数或连续学习天数。

#### 牌组进度

牌组详情至少返回：

```text
card_count
due_count
mastered_card_count
review_count
mastery_ratio
```

其中 `mastered_card_count` 的本期口径为 `mastered_count >= 3` 的卡片数；`mastery_ratio = mastered_card_count / card_count`，当 `card_count = 0` 时为 0。

### 5.16 数据看板（FR-16）

#### 需求说明

数据页必须由服务端真实聚合数据驱动，替换当前前端的固定示例数值和固定柱状图。默认展示当前自然周，周起始日采用周一，时区使用用户或设备上报的 IANA 时区。

#### 指标与口径

| 指标 | 本期定义 |
| --- | --- |
| 周活动 | 当前周每天的复习事件数量，以及本周总复习事件数。 |
| 周变化率 | `(本周复习事件数 - 上周复习事件数) / 上周复习事件数`；上周为 0 时返回 `null`，客户端展示“暂无对比”。 |
| 周目标完成率 | `min(本周复习事件数 / weekly_goal, 1)`；`weekly_goal` 未配置时返回 `null`。 |
| 回忆正确率 | 当前统计周期内 `GOOD` 事件数 / 全部复习事件数。 |
| 首次答对率 | 每张卡首次产生的复习事件为 `GOOD` 的卡片数 / 首次复习卡片数。 |
| 记忆保持率 | 当前统计周期内，在非首次复习事件中为 `GOOD` 的事件数 / 非首次复习事件数。 |
| 连续学习天数 | 截至用户本地当天、连续至少有一条复习事件的自然日数。 |
| 已掌握卡片 | 当前主体下 `mastered_count >= 3` 的去重卡片数。 |

服务端接口应同时返回指标值、统计周期、时区和无数据标记。分母为 0 的比率必须返回 `null`，不得以 0% 冒充实际结果。

### 5.17 偏好与 DeepSeek API Key（FR-17）

#### 偏好设置

- 主题模式（跟随系统、浅色、深色）可继续仅保存在客户端；不要求服务端同步。
- 若后续确认账户体系，可扩展主题和周目标的云端同步；本期接口不以此为前置条件。

#### API Key 校验与使用

- 客户端提供“验证并保存”入口，服务端应返回 `AVAILABLE`、`INVALID`、`INSUFFICIENT_BALANCE` 或可展示的通用失败状态。
- API Key 不得进入业务日志、分析系统、任务明细或错误响应；禁止返回完整 Key，仅可返回脱敏标识或状态。
- 生成任务必须能使用经验证的 Key；Key 的传递与存储方式遵循第 11 章的待确认决策。未确认前，不能将当前前端的本地演示校验视作正式验收。

### 5.18 客户端接口与状态约定（FR-18）

- 所有资源读取接口需按当前数据主体隔离；写入、删除、任务启动、继续任务和复习事件接口均需支持幂等键。
- 长任务查询至少返回 `task_id`、`status`、`stage`、已生成卡片数、目标牌组、失败码、是否可继续和 `updated_at`，以支持前端的生成中、暂停、完成三种页面状态。
- 客户端收到网络失败、超时或可恢复服务端错误时，应保留操作上下文并提供重试；服务端应提供稳定、可本地化映射的错误码。
- 服务端时间是到期判断和统计分桶的权威时间；客户端仅用于展示和离线事件排队。

## 7. 非功能需求

### 7.1 数据安全

#### DeepSeek API Key

- API Key 仅用于发起模型请求。
- API Key 不得写入业务日志、监控数据或分析系统。

#### PDF 文件

- 文件传输必须使用 HTTPS。
- 文件访问应使用基础权限控制。
- MVP 不增加文件级加密或额外密钥管理体系。

#### 日志

日志不得记录：

- 用户 API Key；
- 完整 PDF 内容；
- 完整 Prompt。

#### 服务端访问控制

- 所有牌组、卡片、PDF、任务和复习数据均必须按数据主体隔离；不得仅凭资源 ID 访问他人数据。
- 服务端应校验资源归属和操作权限，并在删除牌组时级联删除或不可见化其关联卡片、复习状态和事件。
- 生产环境的 PDF、模型调用和统计接口必须通过认证后的安全传输访问。具体认证方式见第 11 章待确认项。

### 7.2 可靠性

- 正式生成任务必须支持分批执行和断点续传。
- 已完成批次不得重复执行。
- 已入库卡片不得重复写入。
- 失败任务必须保留已完成结果及可恢复游标。

## 9. MVP 验收标准

### AC-01：PDF 解析

- 具有可提取文本层和可识别目录的 PDF 能进入章节确认流程。
- 无法解析出可用目录结构时，任务停止并展示错误。
- 系统不要求支持 OCR、扫描版或图片型 PDF。

### AC-02：章节配置

- 用户可以修改章节名称、起始页和结束页。
- 用户可以选择一个或多个章节。
- 用户不能拆分、合并或拖拽调整章节顺序。

### AC-03：样卡

- 每次生成固定输出 3 张样卡。
- 三档难度各有 1 张样卡。
- 卡片类型固定为 2 张普通问答卡和 1 张判断题。
- 样卡不能编辑，且不会写入牌组或正式统计。

### AC-04：正式生成与入库

- 用户接受样卡后，系统能够按知识点分批生成正式卡片。
- 只有通过 Schema 校验的卡片会写入目标牌组。
- Rubric 评分不影响 Schema 合法卡片的入库。
- 系统不会因 Rubric 评分执行自动修复、淘汰或补生成。

### AC-05：任务恢复与幂等

- 生成中断后，已生成并入库的卡片仍然保留。
- 用户继续任务时，系统能从保存的游标继续处理。
- 已完成批次不会重复执行。
- 同一 `generation_item_id` 不会重复入库。

### AC-06：单卡重写

- 用户可以对正式卡片发起重写。
- 新版本仅在通过 Schema 校验后替换原卡。
- 重写失败时，原卡保持不变。

### AC-07：质量与缓存数据

- 系统能够记录单卡 Rubric 评分及整批质量统计。
- 系统能够记录 Prompt Cache 的命中 Token、未命中 Token 和输出 Token。
- Rubric 和 Cache 数据异常不应改变既定的卡片入库规则。

### AC-08：敏感信息保护

- 日志和分析系统中不出现用户 API Key。
- 日志中不记录完整 PDF 内容或完整 Prompt。

### AC-09：牌组与卡片联调

- 用户可新建牌组、向已有牌组添加单张卡片或批量导入预览后的卡片；重新提交同一幂等键不会造成重复写入。
- 牌组列表和详情展示服务端返回的真实卡片数、待复习数和进度，不依赖本地演示数据。
- 删除牌组后，其卡片和复习数据不再出现在当前数据主体的读取结果中。

### AC-10：复习与统计联调

- 到期复习仅返回当前服务端时间已到期的卡片；自由刷题不创建复习事件。
- 提交 `AGAIN`、`HARD`、`GOOD` 后，复习状态、牌组进度和复习事件正确更新；离线重试同一 `client_event_id` 不重复计数。
- 数据页能按当前自然周展示真实每日活动、总复习数、周变化率、周目标完成率、三项正确率指标、连续学习天数和已掌握卡片数；无数据时按约定返回空态而非固定示例值。

### AC-11：API Key 联调

- “验证并保存”可返回可用、无效、余额不足和通用失败状态，且前端能据此展示状态。
- API Key 不出现在服务端日志、任务详情、分析数据、客户端持久化明文或接口响应中。

## 10. MVP 质量策略总结

MVP 采用以下质量路径：

```text
生成 → Schema 校验 → 入库 → Rubric 观测 → 基于数据迭代
```

MVP 不采用以下自动化闭环：

```text
生成 → 评分 → 修复 → 淘汰 → 补生成 → 重平衡
```

本版本以验证 PDF 制卡核心链路的真实可用性为首要目标，同时建立可用于后续优化的质量与运行数据基础。
