# 闪卡 App 前端对接与联调交接

更新日期：2026-08-12  
适用客户端：`Front` Android Jetpack Compose

接口契约以 [交接文档.md](交接文档.md) 与线上 OpenAPI 为准；本文只保留联调所需的结论和待确认项。

## 当前联调状态

- 牌组、卡片、复习、导入、PDF、API Key、看板均以服务端为唯一业务数据源；本地不保存业务数据或 API Key。
- 当前生产/真机地址：`https://shanka.kbzz1.top`；Android 模拟器 debug 才使用 `http://10.0.2.2:8000`。当前路径无 `/v1` 前缀。
- 牌组改名、卡片编辑、卡片删除、PDF 章节删除已接入服务端接口。删除动作先从当前界面移除，服务端失败才恢复，并仅短暂提示“删除失败”。
- 样卡预览始终渲染 `front` / `back`；响应外层的样卡数组同时兼容 `samples`、`sample_cards`、`cards`、`items`、`data` 及线上契约允许的其他数组字段。
- API Key 提交后立即查询 `GET /api-key/status`，仅查询到 `AVAILABLE` 才视为服务端可用；不会仅依据 `PUT /api-key` 的 `200` 判断。
- 点击“开始生成”会先查询 API Key 状态。未配置、无效或余额不足时不创建牌组或任务，并提供前往设置的提示；任务接口仍返回 API Key 错误时也会显示失败原因。
- 写操作均带 `Idempotency-Key`，仅 `429` 按 `Retry-After` 用原键重试一次；删除接口可正常处理后端 `204` 空响应。
- debug 日志保存至 Logcat 与应用私有 `files/shanka-network-debug.log`（最大 256 KiB）。日志已包含本地 trace、后端 `X-Request-ID`、路径、状态码、耗时、重试次数、错误码和 PDF 状态；不包含设备 ID、幂等键、API Key、PDF/卡片内容或原始响应。

取证命令：

```bash
adb exec-out run-as com.qiuzhao.flashcards cat files/shanka-network-debug.log
```

## 已确认产品边界

### PDF 上传与解析

后端已验证文字版 PDF 可完成 `201 → PARSED`（12 章节）。72.9MiB 扫描版 PDF 的 `FAILED / PDF_PARSE_FAILED` 是预期边界：文件没有可提取文本层，当前产品不提供 OCR 兜底。前端按失败状态终止流程即可。

如需支持扫描版 PDF，应作为 OCR 能力另行排期；不属于当前联调阻塞。

### 任务暂停

后端确认没有暂停接口，`PAUSED` 为预留状态；当前“暂停生成”只保留现有本地展示状态，不能控制服务端任务。
