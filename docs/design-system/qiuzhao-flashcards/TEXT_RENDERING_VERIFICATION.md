# Compose 文字裁切：诊断与修复方法

适用于本项目所有需要按 Figma 固定文字框实现的 Compose 界面。目标不是让截图「看上去差不多」，而是在真机上证明字形没有被裁切，且仍保持 Figma 的视觉基线。

## 1. 先确认裁切位置与设计基线

1. 从对应的 Figma 节点读取字体、字号、行高、字距、容器高度与上下间距。
2. 在连接的物理设备上进入同一页面，截取包含问题文本的截图。
3. 区分三种问题：文字自身被约束裁切、父布局/圆角容器裁切、以及字体内边距导致的视觉偏移。不能只凭截图猜测原因。

## 2. 用真实排版数据判断是否裁切

临时给目标 `Text` 添加 `onTextLayout`，记录：

- `layout.size.height`
- `getLineTop(0)` / `getLineBottom(0)`
- `getLineBaseline(0)`

若 `getLineBottom(0)` 超出 `Text` 的实际测量高度，或超出父文字框，则该文字在当前约束下存在裁切风险。日志只能作为定位工具；修复完成前必须移除。

## 3. 保留 Figma 布局框，放开 Android 的实际文字测量

Figma 常给出例如 `40px` 或 `16px` 的视觉行框；Android 字体的真实行高可能更大。不要把 `Text` 直接锁死在这个高度。

1. 外层 `Box` 保持 Figma 的固定高度，确保后续元素位置不变。
2. 内层 `Text` 用真机测得的完整高度（例如 `requiredHeight`）参与测量。
3. 在外层框中 `Center` 对齐，使字形回到 Figma 的视觉基线；外层本身不裁剪子元素。
4. 采用 `figmaCardTextStyle()`，即 `includeFontPadding = false`，避免 Android 额外字体内边距把文字整体向下推。
5. 若文字进入相邻元素的间距区域，必须检查可见字形是否重叠；不能仅因布局高度未变就认为正确。

## 4. 验收顺序

1. 重新构建并安装到物理设备。
2. 重查排版数据：每行的底部不得超过文字自身的测量高度。
3. 截图与 Figma 导出图比较：文本顶部、基线、下一行/下一组件的位置、圆角边界均需匹配。
4. 复查同一复用组件的白色、浅色等全部变体，以及中英文/数字等不同字符形态。
5. 删除临时日志和诊断代码后，再做一次干净构建与真机截图。

## 常见错误

- 为防裁切打开 `includeFontPadding = true`：通常会让内容整体下移，偏离 Figma。
- 只扩大外层卡片高度：会破坏卡片间距与页面滚动位置。
- 只扩大文字框但不控制外层布局：会将标签/按钮推下，造成新的布局错误。
- 修复一个字符串后直接交付：数字、英文和中文的字体度量不同，必须覆盖验证。
